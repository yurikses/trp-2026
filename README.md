
## Название проекта
Rubdiff
## Назначение
Автоматизированный сбор и сравнение цен на товары из различных интернет-магазинов для поиска наилучших предложений.
## Целевая аудитория
  - Покупатели, желающие сэкономить
  - Аналитики рынка
  - Владельцы интернет-магазинов

## Описание предметной области
Система агрегирует данные о ценах на товары из множества онлайн-магазинов, предоставляя пользователям актуальную информацию для принятия решений о покупке.
## Основные сущности

  - Пользователь - зарегистрированный клиент системы
  - Товар - карточка товара с характеристиками
  - Магазин - источник данных о ценах
  - Цена - стоимость товара в конкретном магазине
  - Категория - группа товаров

Все сущности представлены классами `Category`, `Product`, `Store`, `Price` и
`User`. Объекты взаимодействуют через ссылки: товар хранит объект категории,
цена хранит товар и магазин, а пользователь хранит список избранных товаров.
Каждый класс имеет `__init__`, `__str__`, `to_dict` и `from_dict`.

## Основные функции

  - Поиск товаров по названию и категориям
  - Сравнение цен в разных магазинах
  - Добавление товаров в избранное

## Репозиторий данных

`DataRepository` в `storage.py` содержит коллекции объектов и базовые CRUD-
операции для всех сущностей: создание, получение, изменение и удаление.
Удаление товара или магазина также удаляет связанные цены, а удаление товара
убирает его из избранного пользователей.

Функции `load_data` и `save_data` преобразуют объекты в JSON и обратно. Для
товаров и категорий используется `products.json`, остальные сущности находятся
в `stores.json`, `prices.json` и `users.json`.

## Запуск

```bash
python main.py
```

При запуске данные загружаются из каталога `data` в файлы JSON. Программа
обрабатывает некорректный выбор пункта меню и нечисловой ID товара.

## Проверка

```bash
pytest -q
flake8 .
```

Код разделен по модулям: `products.py`, `stores.py`, `prices.py`, `users.py`
и `storage.py`. Тесты находятся в каталоге `tests` и проверяют поиск,
сравнение цен, CRUD, связи объектов и round-trip сохранения JSON.

## Веб-интерфейс Django (ПР3)

Консольная программа сохранена и продолжена веб-слоем на Django 5.2.
`manage.py` находится в корне репозитория, а проект Django размещен в
`config/`. Приложения `home`, `categories`, `products`, `stores`, `prices` и
`users` отвечают за главную страницу и основные сущности предметной области.
Они используют `storage.load_data` и исходные JSON-файлы, поэтому перенос в
Django ORM, формы и авторизация не требуются.

Общий HTML-каркас находится в `home.views.render_page`: он подключает
Bootstrap 5.3 через CDN и содержит навигацию. Списки используют Bootstrap
`list-group`, а страницы деталей показывают связанные объекты в карточках.
Язык проекта установлен в `ru-ru`, часовой пояс — `Europe/Moscow`.

### URL и представления

| URL | Назначение |
| --- | --- |
| `/` | Главная страница и навигация (`home`) |
| `/categories/`, `/categories/<id>/` | Список и детали категорий |
| `/products/`, `/products/<id>/` | Список и детали товаров с предложениями |
| `/stores/`, `/stores/<id>/` | Список и детали магазинов с предложениями |
| `/prices/`, `/prices/<id>/` | Список и деталь цены |
| `/users/`, `/users/<id>/` | Список и профиль пользователя с избранным |

Маршруты подключены через `include` в `config/urls.py`, а каждое приложение
содержит собственный `urls.py`. Для идентификаторов используются конвертеры
`<int:..._id>`. У старого класса `Price` нет отдельного поля ID, поэтому его
деталь адресуется порядковым номером записи в загруженном списке.

### Запуск веб-приложения

```bash
python manage.py migrate
python manage.py runserver
```

Проверки проекта:

```bash
python manage.py check
flake8 .
pytest -q
```
